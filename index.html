Ended up designing products.

03 / process

Four things I do
on every project.

01

Chase the real problem.

Briefs usually describe a solution someone already picked. The useful work is finding what's underneath it.

02

Push back once, properly.

If I think a call is wrong, I'll say so with a reason — then build what you decide. It's your product.

03

Design the boring states.

Empty, loading, error, offline, the name that's too long. That's where products feel cheap, so that's where I'm stubborn.

04

Hand over something buildable.

Consistent spacing, real components, specified states, motion in milliseconds. If a developer has to guess, I'm not done.
